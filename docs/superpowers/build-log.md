- **Ruling C4:** T11's setup stubs `agent.get` with `agent_status: "working"`, not `"idle"`. — With `idle` and `settle_ms: 10`, the spawned session flushes its mailbox within milliseconds, so `Hq.Session.pending("worker-a")` races the assertion. `working` holds the mail and makes the test deterministic. No other T11 test depends on the status. — Cost if wrong: a flaky test that passes locally and fails in CI.
- **Ruling C5:** T13's `put_self_name` adds `pane_id` from `$HERDR_PANE_ID` unconditionally, not only when `name` is absent. — As written, `hq register foo` produces `%{"name" => "foo"}` with no `pane_id`, so the handler's `register` clause cannot match and it falls through to `unknown_verb`. That breaks the entry point to the entire system, and no T13 test covers the path. T13 must also add a test for it. — Cost if wrong: `hq register` is dead on arrival.
- **Ruling C6 (accepted risk):** `refresh_status/1` sets status directly, bypassing T12's `put_status/2`, so a session adopted while ALREADY blocked does not notify its parent until its next transition. — Entering `blocked` always emits a status event, which does route through `put_status`; only the adopt-into-blocked case is missed. Fixing it would mean routing `refresh_status` through `put_status`, which risks a spurious notice on every reconnect. — Cost if wrong: one missed notice in a narrow case; the parent can still see it via `hq ls`.
